# Android-игры — отдельный конвейер (НЕ трогает iOS-конвейер)

Читать при `/droid-game`, `/droid-assets`, `/droid-pack`. Правила iOS (`CLAUDE.md` и
остальные файлы `rules/`) к Android-проектам НЕ применяются, кроме явно перенесённых сюда.
Выведено из сборки <reference game> 03–04.09.2026 со всеми правками оператора.

## Пути и жизненный цикл
- Новая игра СОЗДАЁТСЯ на рабочем столе: `~/Desktop/<Имя>/`. Рабочий стол не захламлять
  ничем, кроме папки текущей игры и файлов сдачи (zip/apk).
- Готовая игра ПЕРЕЕЗЖАЕТ в `$PIPELINE_ROOT/android/`.
- **Эталон (read-only): `$PIPELINE_ROOT/android/<reference game>/`** — паттерны читать
  оттуда, по этим путям НИКОГДА не писать. Аналог Misframe для iOS.
- Тестирует оператор сам: эмуляторы Pixel_8 и Pixel_Tablet уже созданы. Агент приложение
  НЕ запускает и НЕ устанавливает (иначе сжигается onboarded-флаг первого запуска).
  Видео для заказчика — скрипт `~/Desktop/Запись игры.command` (double-click → Enter →
  mp4 на столе и в буфере).

## Стек (зафиксирован, работает — не обновлять без причины)
- Kotlin 2.0.21, Jetpack Compose BOM 2024.12.01, AGP 8.9.2, Gradle wrapper 8.11.1.
- minSdk 26, **compileSdk/targetSdk 36** — Google Play ТРЕБУЕТ target ≥36, с 35 реджект
  «must target at least API level 36» прямо на заливке (поймано 04.09.2026 на <reference game>).
  ТОЛЬКО портрет, весь UI на английском.
- Каждая НОВАЯ заливка в Play Console требует НОВОГО versionCode — даже если прошлую
  сборку отклонили: консоль её уже видела. Пересобрал для заливки → +1 к versionCode.
- Сборка из CLI: `JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home ./gradlew assembleDebug`
- Каркас нового проекта: скопировать из эталона `gradle/`, `gradlew*`, `gradle.properties`,
  `local.properties`, структуру `*.gradle.kts` (сменив namespace/applicationId — свой
  reverse-DNS на игру), themes/colors/manifest по образцу. Шрифт — свой OFL из
  google/fonts GitHub (НЕ повторять Baloo2 из <reference game>), кладётся в `res/font/`.

## Архитектура (роли как в эталоне, ИМЕНА — доменные под тему игры)
- `MainActivity` — только точка входа (edge-to-edge + setContent).
- `ui/AppRoot` — гейт и роутер: Loader → СРАЗУ ИГРА → Result → Menu.
  **Мгновенный старт — требование заказчика, стандарт для всех игр:** лоадер ≤3.5 сек,
  тап пропускает, авто-переход прямо в геймплей (не в меню!). Онбординг-слайдов НЕТ —
  обучение подсказками внутри первого раунда, флаг ставится после первого завершённого.
- Единый `ViewModel` (AndroidViewModel): enum Screen + immutable UiState + StateFlow.
  Вся логика там, экраны только рендерят и зовут методы.
- Персистентность: SharedPreferences + kotlinx-serialization JSON, `ignoreUnknownKeys`,
  дефолты на всех полях, try/catch — битые данные не крашат и не стирают.
- Звук: singleton (роль SoundBox) — SoundPool на эффекты + MediaPlayer-луп на музыку,
  старт из первой композиции AppRoot, каждая операция guarded, пауза по lifecycle
  (ON_STOP/ON_START). Звуки ГЕНЕРИРУЮТСЯ python-скриптом (wave/struct/math, см. эталонный
  подход): click/hop/bank/crash/rev + муз. луп ~10 сек; свои тона под тему.
- Игровой цикл: `withFrameNanos` в LaunchedEffect(phase), `advance(dt)` с dt-клампом
  (≤0.05с — рывок кадра не телепортирует физику). Вся симуляция — чистые функции
  состояние→состояние.
- `@Preview` — на стейтлес-экранах (Loader и т.п.); экраны с VM смотрятся эмулятором.

## Оригинальность (граница — жёсткая)
- Флоу-образец даёт МЕХАНИКУ и структуру напряжения, НЕ содержание. Своё: название, слоган,
  сеттинг, персонажи, палитра, шрифт, звуки. Чужие имена/лого/арт/фирменные цвета конкретных
  продуктов не имитировать.
- Никаких ставок/валют/баланса в кассовом смысле: монеты/очки, push-your-luck — через
  риск потерять несобранное, а не через «bet».
- Брендированные заглушки под чужой продукт и ветвление «модеру одно, юзеру другое» —
  не делаем ни в каком виде.
- Описание стора = только реальные фичи сборки.

## Арт (рукописный вектор, пока нет ассетов дизайнера)
- Сцена с персонажами масштабируется ЯВНОЙ единицей u = рост персонажа; вызывающий экран
  сам выбирает u из своей геометрии. Никогда не растить сцену от высоты ЭКРАНА.
- Мир геймплея — в МЕТРАХ: pxPerM = ширина/`~15`; колесо/препятствия/декор/деревня — всё
  через pxPerM. Реквизит фона — параллакс ~0.85 и ноги НА земле; в сцене мастерской/меню
  фоновый реквизит отключать (propsOn=false), чтобы не лез в композицию.
- Персонажи: черты лица ЦЕЛИКОМ внутри головы (глаза с белками и бликами, брови, нос,
  рот); головной убор НАД бровями; руки — плечо→локоть→кисть с ладонью и большим пальцем,
  длина руки КЛАМПИТСЯ; персонажи привязаны к своим инструментам в u-единицах, НЕ в долях
  ширины экрана (иначе на широких экранах конечности растягиваются).
- Анимация — от одного clock (timeSec в стейте, тикает в advance): дым, флаги, качание,
  «насосное» движение рычага (дуга туда-сюда, не 360°), дыхание стоящих персонажей.
  Каждый персонаж в кадре обязан быть чем-то занят.
- Юайс геймплея: сквош при приземлении, пыль, тряска камеры на краше, таблички множителей
  по трассе, пульсирующий «!» над приближающимся препятствием.

## Ассеты от дизайнеров — метод внедрения (проверен)
1. Файлы приходят в `~/Downloads`. КАЖДЫЙ посмотреть глазами (Read) + `sips` размеры/alpha.
2. **Замерить bbox контента** (python PIL по альфе) — у сгенерённых PNG огромные прозрачные
   поля, из-за них вёрстка «разъезжается». ОБРЕЗАТЬ по контенту (ffmpeg crop) ДО вёрстки.
3. Большие фоны жать: ffmpeg scale (фон → jpg ~высота 1800; спрайты → png, разумная ширина).
   Имена в drawable: `[a-z0-9_]` строго.
4. Движущиеся части (стрелка, каретка) — НАТИВНО, из ассета только неподвижное; если
   подвижное впечатано в ассет — расшить (крой + зеркало половины и т.п.).
5. Зоны игровой ЛОГИКИ и зоны ВИЗУАЛА — одни и те же доли одной системы координат
   (общая осевая переменная), чтобы физически не могли разойтись.
6. Раскладка поверх ассета-подложки: BoxWithConstraints, все размеры — доли от подложки,
   аспекты — из РЕАЛЬНЫХ обрезанных размеров файлов. Кнопки-ассеты: clickable без
   индикации + scale-прижатие через graphicsLayer.
7. Хореография «полёта» в креативах: точки отскока = позиции объектов (попадание
   гарантировано конструкцией), сквош после отскока, объект подпрыгивает + искры,
   шлейф-ассет поворачивается по вектору скорости, посчитанному в РЕАЛЬНЫХ пикселях
   экрана (не в квадратных координатах).

## Честность геймплея (проверять АРИФМЕТИКОЙ до сдачи)
- Хитбокс: круг-против-ящика с щадящим радиусом (~0.72 от визуального) — «на экране
  перелетел» обязан означать «пролетел».
- Высота ЛЮБОГО препятствия < апекса базового прыжка (посчитать vy²/2g и сравнить).
- Прогрессивная сложность: потолок скорости растёт с дистанцией (с абсолютным клампом
  читаемости), интервалы сжимаются (с полом), пары/связки — после разогрева и с
  гарантированным местом для второго прыжка. Худший случай спавна обязан быть проходимым
  на бумаге, не «на глаз».
- Управление: и тап по экрану, и явные кнопки (HOP/BANK); подсказка первого раунда.

## Геймификация (обязательный минимум)
Монеты-пикапы на трассе (дуги над препятствиями + дорожки), магазин апгрейдов с РЕАЛЬНЫМ
эффектом на формулы (не косметика), ранги с XP-лестницей, ачивки с прогресс-барами к
измеримым целям, уровни сложности, открываемые рангом. Каждая цифра UI совпадает с тем,
что считает движок.

## UI-кит
Кламп контента 560dp по центру (телефон/планшет одной вёрсткой), панели: тень + градиент +
двойная рамка; кнопки «игрушечные» 3D (лицевая грань на тёмном ребре, прижатие вниз +
spring-scale); прогресс-бары с градиентом; палитра ТОЛЬКО из объекта темы, светлота и hue —
свои у каждой игры.

## Сдача (`/droid-pack`)
1. `./gradlew clean`, свежий `assembleDebug`, APK скопировать на стол `<Имя>.apk`.
2. zip БЕЗ `app/build/`, `build/`, `.gradle/`, `local.properties`, `.DS_Store`:
   `cd ~/Desktop && zip -r <Имя>.zip <папка> -x ...` (см. эталонную команду).
3. Проверить `unzip -l`: врапперы (`gradlew`, `gradlew.bat`, `gradle/wrapper/*`) внутри,
   мусора нет.
4. `STORE_LISTING.txt` в корне проекта: EN, БЕЗ эмодзи, структура: Short (≤80 симв.) /
   Long (хук-абзац, вопрос, How to Play, Game Features, финал-призыв) / Keywords (10) /
   Category. Только реальные фичи. Название игры в тексте не употреблять.
5. Оба файла отправить оператору (SendUserFile) и напомнить: переиспользуемая папка build
   отрастает при каждой сборке — это норма, чистится `gradlew clean`.
