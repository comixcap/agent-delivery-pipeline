# Вёрстка SwiftUI — полный справочник

Читать ОБЯЗАТЕЛЬНО перед: любой вёрсткой экрана, починкой ширины/сетки/колец/графиков,
работой с intro-артом, обложками, тёмной темой. Ядро правил — в `$HOME/.claude/CLAUDE.md`,
здесь полные формулировки, арифметика и примеры кода.


⚠️ **Корневое правило ширины (решает сразу два бага).** `ScrollView` в SwiftUI — это
`UIScrollView`, и его `contentSize` берётся из фактического layout контента. Если хоть один
ребёнок оказался шире вьюпорта, `contentSize.width` превышает границы, и скролл начинает
**таскаться по горизонтали пальцем** вместе с вертикальным скроллом, а ряды уходят за оба края.
Переполнение по ширине и «контент перетаскивается вместо скролла» — это ОДИН баг.
Лечение: все вертикальные скроллы экранов — через контейнер, который отдаёт контенту ТОЧНУЮ
ширину вьюпорта (`ScreenScrollView` из эталона: `GeometryReader` + `.frame(width: geo.size.width)`
+ `.clipped()`). Где нужен `ScrollViewProxy` — тот же кламп вручную.
Оверсайз-арт (декоративные круги, карты, свечения) применяется ТОЛЬКО через `.background(...)`
либо внутри `GeometryReader` с жёстким `.frame(width: geo.size.width)`. Свободным соседом в
`ZStack` — никогда: `ZStack` принимает размер самого широкого ребёнка и растягивает весь экран.

⚠️ **Корневое правило размера — то же самое, но по ОБЕИМ осям и для любого размера вью.**
Правило выше выглядит как «про большой арт и про ширину», и из-за этого пропускается там, где
декорация мелкая. Настоящая формулировка такая: **градиент (`LinearGradient`/`RadialGradient`/
`AngularGradient`), `Color`, `Shape`/`Rectangle`/`Capsule` без `.frame`, `Spacer` — это
БЕЗРАЗМЕРНЫЕ вью.** У них нет собственного размера, и они принимают ВСЁ, что им предложат.
Свободным ребёнком `ZStack` такой вью становится самым большим ребёнком и НАЧИНАЕТ САМ ЗАДАВАТЬ
размер контейнера — и по ширине, и по высоте. Это не про «оверсайз-арт», это про любую
декоративную подсветку внутри кнопки, ячейки, чипа, карточки.
Лечение всегда одно: декорация — это `.background(...)` или `.overlay(...)` НА контенте,
а не сосед контента. Фон/оверлей по определению принимает размер контента и физически не может
влиять на layout. Свободным соседом в `ZStack` безразмерный вью допустим ТОЛЬКО когда сам `ZStack`
сразу после этого получает явный `.frame(width:height:)`.
Симптом, по которому это узнаётся мгновенно: **элемент интерфейса неожиданно занял пол-экрана**,
или **соседние ячейки одного ряда встали на разной высоте** (у одной есть декорация, у других
нет → `HStack`/`ZStack` берёт высоту самой высокой, остальные центрируются в ней и «разъезжаются»).

- **Таббар — furniture с ФИКСИРОВАННОЙ геометрией, а не растущий контейнер.** Ячейка обязана
  иметь явный `.frame(maxWidth: .infinity, minHeight: 48)`, и выбранное/невыбранное состояние
  обязано раскладывать ОДИНАКОВЫЙ контент (тот же размер знака, та же одна строка подписи с
  `lineLimit(1)`) — меняются только цвет и стиль знака (`.solid`/`.carved` vs `.outline`/`.etched`),
  но не размеры. Иначе высота бара скачет при переключении вкладки.
  Подсветка выбранной вкладки (капсула, ниша, свечение, подчёркивание) — ВСЕГДА через
  `.background(...)`, НИКОГДА соседом в `ZStack`: см. корневое правило размера выше. Реальный баг:
  `LinearGradient` подсветки стоял свободным соседом, растянулся до максимума и задал высоту
  ячейки → таббар занял пол-экрана, а четыре невыбранные ячейки центрировались в этой высоте и
  визуально «разъехались» относительно выбранной. Плюс `.denseTypeLimit()` на весь ряд, чтобы
  крупный Dynamic Type не раздувал бар.
- `ScrollView`/`List`: всегда `.padding(.bottom, 100)` (место под кастомный таббар).
- Фоны: всегда `.ignoresSafeArea()` на контенте (НЕ на `NavigationStack`).
- Контейнеры и элементы: `.frame(maxWidth: .infinity, alignment: .leading)`, чтобы тянулись по ширине.
- Top-level `VStack` в `ScrollView` — обязательно `.frame(maxWidth: .infinity, alignment: .leading)`.
- Карточки — `.frame(maxWidth: .infinity, alignment: .leading)` внутри background.
- Жест внутри скролла (pan карты, drag) не должен конкурировать со скроллом: включать его
  только когда он осмыслен (например, панорамирование — лишь при зуме > 1), с `minimumDistance`.
  `SimultaneousGesture` со скроллом даёт «и скроллится, и таскается».
- Чипы равной ширины: растягивать нужно и кнопку, и её фон — иначе пилюли будут разной длины.
- Ряды из 3+ chip/tag не мешать с растягивающимся контентом в одном HStack — выносить в отдельный ряд / горизонтальный ScrollView.
- Длинные тексты: `.lineLimit(...)` или `.fixedSize(horizontal: false, vertical: true)`.
- padding только на одном уровне (root VStack), не дублировать на каждой карточке.
- ⚠️ **СЕТКА/ДОСКА/ЛЮБОЙ КАСТОМНЫЙ РАСКЛАД НА `.offset` — СРАЗУ ПЕРЕПИСЫВАТЬ НА `VStack`/`HStack`, НЕ ПРОВЕРЯЯ.** Симптом: сетка стоит не по центру, а сдвинута вправо-вниз примерно на половину области, часть клеток уезжает за экран, соседние подписи оказываются поверх неё; тап при этом попадает НЕ в ту клетку, на которую нажали. Причина: `.offset` НЕ участвует в layout — `ZStack`, у которого все дети только смещены оффсетами, берёт размер САМОГО БОЛЬШОГО ребёнка (= одна клетка), и следующий `.frame(width:height:alignment:.center)` центрирует этот крошечный блок, унося начало координат на `(область − клетка)/2` по обеим осям. Дальше все оффсеты отсчитываются от уехавшего угла, а математика жеста (`point(at:)`) считает от настоящего угла области → картинка и хит-тест расходятся. Правильно:
  ```swift
  ZStack(alignment: .topLeading) {
      Color.clear                                   // держит систему координат = вся область
      VStack(spacing: s) { ForEach(rows) { r in     // НАСТОЯЩИЙ layout, а не оффсеты
          HStack(spacing: s) { ForEach(cols) { c in tile(r, c).frame(width: cell, height: cell) } }
      } }
      .frame(width: geo.size.width, height: geo.size.height)   // центрируется штатно
      if dragging { liftedTile.offset(x: originX + tx, y: originY + ty) }  // оффсет — ТОЛЬКО для «поднятого» пальцем
  }
  ```
  Стек получает ровно `boardWidth × boardHeight`, его края попадают точно в `insetX/insetY` из метрик — позиция и попадание больше не могут разойтись. `.offset` допустим ТОЛЬКО для элемента, который временно летает над раскладом (перетаскиваемая фишка), и никогда — для самого раскладa. Пустую клетку отдавать как `Color.clear.frame(width: cell, height: cell)`, иначе ряд схлопывается и сетка едет. Проверять: компонент доски обычно переиспользуется на 5–10 экранах — баг глобальный, чинится один раз в компоненте.
- ⚠️ **Плитка/чип с названием сущности: сначала считай, влезает ли текст, потом задавай ширину.** Симптом: подписи под иконками нечитаемы — `.nano`/9pt + `lineLimit(1)` + `minimumScaleFactor(0.7)` на плитке 78pt ужимает «Blood Orange Sorbet» до ~6pt, это каша. Правило: имя сущности — минимум `.micro` (12pt) и **две строки** с `.multilineTextAlignment(.center)`, `minimumScaleFactor` не ниже 0.85, ширина контента ≥ 96pt. Чтобы ряд не стал рваным при разной длине имён, под блок имени резервируй фиксированную высоту через `@ScaledMetric(relativeTo: .caption) var nameHeight: CGFloat = 32` + `.frame(width:height:alignment: .top)` — высота растёт с Dynamic Type, но все плитки в ряду одинаковые и фоны выравниваются. На плитке с зарезервированной высотой обязателен `.denseTypeLimit()`. Прикидка: при 12pt полужирном ~6.5pt на символ, значит на 96pt влезает ~14 символов в строку → 28 символов в две строки (это и есть разумный лимит имени в редакторе).
- `sheet` с опциональным state → `.sheet(item:)` (атомарная презентация, без гонок).
- Кастомный `Equatable` на `@State`-структурах с мутацией полей — частая причина «вью не обновляется».
- Intro-арт (Loader/Onboarding): элементы у краёв арт-зоны в `GeometryReader` обрезаются наполовину — арт-зона обычно `.clipped()`. Маппить координаты в безопасную рамку **по ОБЕИМ осям**, не только по ширине: `inset = размер_элемента/2 + 6`, `x = inset + (w − 2·inset)·fx`, `y = inset + (h − 2·inset)·fy`. Для кольца радиус меряется до ЦЕНТРА элемента, поэтому `r = min(w,h)/2 − элемент/2 − 6`, а НЕ доля от половины (`min(w,h)·0.39` ставит верхний элемент ровно на свой радиус от края → срез). Арт-зона низкая (~210pt), так что режет почти всегда именно по вертикали. Проверять арифметикой обе крайности (SE 375pt и iPad) — координата крайнего элемента ± его половина обязана лежать внутри `0…h`.
- Короткий слайд онбординга в top-aligned скролле прилипает к полосе прогресса, а перед нижней кнопкой зияет пустота («всё смещено вверх»). Общий `ScreenScrollView` выравнивает по верху и правится не должен — заводить в файле онбординга свой контейнер с тем же клампом ширины плюс `.frame(minHeight: geo.size.height, alignment: .center)`: короткий слайд центрируется, длинный (крупный Dynamic Type, добавленные участники) по-прежнему скроллится. Арт и текст должны ехать ОДНИМ блоком внутри этого контейнера, а не «арт фиксированной высоты + отдельный скролл под ним».
- Кастомный vector-арт (`Canvas`/`Shape`/`GeometryReader`: обложки, баннеры, лоадер, фон) РАСТЯГИВАЕТСЯ на iPad, когда размеры завязаны на ширину контейнера. Правило: размеры объектов/силуэтов/орба/обводок — от ПОСТОЯННОГО измерения (у горизонтального баннера — высота `h`, `orb=h*1.15`, `line=max(1.6,h*0.02)`) или в абсолютных pt, НЕ в долях ширины. Повторяющийся паттерн (рельеф/волны) — постоянная длина волны в пунктах: `phase = x/waveLength` (`waveLength≈h·k`), а не «N циклов на всю ширину» (`sin(t*2π*const)`, `t=x/w`) → широкий экран показывает БОЛЬШЕ элементов того же размера, а не растянутые. Плотность частиц — `count = max(base, Int(width/шаг))`. Позиция в долях ширины (`x=w*0.24`) — ОК; растягивает именно РАЗМЕР в долях ширины. Не лечить сжатием/центрированием контента (`maxWidth` колонки) — чинить масштаб ВНУТРИ арта. Проверять на iPad-ширине И SE.
- ⚠️ ПРОИЗВОДИТЕЛЬНОСТЬ кастомного vector-арта (обложки/баннеры/лоадер/фон, особенно когда их МНОГО на экране — пикер обложек 8–12 штук, список карточек) — иначе приложение СИЛЬНО лагает в симуляторе. Правила: (1) тяжёлую многослойную сцену (ZStack градиентов/шейпов/Canvas) заворачивай в **`.drawingGroup()`** — композит один раз в кэш-текстуру Metal, дальше прокрутка почти бесплатна. (2) **НИКАКОГО `.blur(radius:)`** в повторяющемся/множественном арте — самый дорогой GPU-оператор, множится на число элементов; «глоу» делай полупрозрачными штрихами бо́льшей толщины или `RadialGradient` с прозрачным краем. (3) Избегай `blendMode(.plusLighter/.screen)` — дорогой оффскрин-композит. (4) **Декоративный арт — статичный**: НЕ вешай `.repeatForever` на сцену, где анимируемое `@State` читается внутри ZStack — SwiftUI перерисовывает и заново растеризует ВСЮ сцену каждый кадр (×N элементов) = главный источник лагов. Нужна анимация — только у ОДНОГО мелкого элемента, вынесенного ОТДЕЛЬНЫМ слоем поверх `.drawingGroup()`-сцены. Памятка: арт не должен делать НИКАКОЙ покадровой работы — нарисовал → сплющил в текстуру → показываешь. (5) **`.drawingGroup()` на ПОЛНОЭКРАННОМ фоне/арте → `.ignoresSafeArea()` ставить ПОСЛЕ `.drawingGroup()`, а не только на внутренних слоях.** `.drawingGroup()` растеризует контент в текстуру размером с layout-границы вью, а они по умолчанию ограничены safe area; если `ignoresSafeArea` только на детях внутри ZStack — текстура «замерзает» по safe-area-рамке и сверху под вырезом / снизу над home-индикатором вылезают **белые полосы**. Правильно: `ZStack{…}.drawingGroup().ignoresSafeArea()` (ignoresSafeArea последним). Проверять верх и низ экрана с вырезом.
- Текст внутри кольца/круглого прогресс-индикатора налезает на обводку: ограничь внутренний контент `innerWidth = size − 2·strokeWidth − 8` через `.frame(width: innerWidth)`, добавь `.lineLimit(1)` + `.minimumScaleFactor(0.5)`; толщину обводки делай зависимой от размера (`max(7, size·0.10)`), чтобы на маленьком кольце оставалось место под текст.
- ⚠️ **Обводка рисуется ПО ЦЕНТРУ пути и вылезает за фрейм на `lineWidth/2` с каждой стороны — фрейм резервирует `size`, а краска занимает `size + lineWidth`.** Симптом: три кольца в `HStack(spacing: 10)` наплывают друг на друга, между ними нет места; выделенная плитка сетки съедает зазор до соседей; кольцо в `HStack` с текстом наезжает на текст. Арифметика: кольцо `size: 94` → `stroke = max(7, 94·0.10) = 9.4` → краска 103.4pt при фрейме 94 → реальный зазор `10 − 9.4 = 0.6pt`. Увеличивать `spacing` — лечение симптома; чинить надо ink. Фиксы: (1) `Circle().stroke(…, lineWidth: w).padding(w / 2)` — внешний край краски встаёт ровно на фрейм (работает и для `.trim`-дуги, `.padding` ставить ДО `.rotationEffect`); (2) для рамок замкнутых фигур — `.strokeBorder(…)` вместо `.stroke(…)`, он инсетит обводку внутрь сам. Пороговое правило: `lineWidth ≥ 3` — обязательно инсетить; `lineWidth 1–1.5` (рамки карточек, чипов) можно оставить, там перелив 0.5–0.75pt и это стандартная практика iOS.
- Ряд из 2–3 колец/круглых индикаторов: не «фиксированный размер + фиксированный `spacing`», а фиксированный размер + `.frame(maxWidth: .infinity)` на КАЖДОМ кольце — остаток ширины делится поровну, и на узком экране ряд не скучивается. Размер подбирать под самый узкий экран: внутри карточки на 375pt доступно `375 − 32 (отступ экрана) − 32 (padding карточки) = 311pt`, значит три кольца по 92 + два зазора по 8 = 292pt, запас 19pt. Константы выносить в одно место (`enum RingRow { size, spacing }`), иначе три экрана разъедутся по размеру колец.
- Прогресс-дуга кольца (`Circle().trim`/обводка) с `AngularGradient` 0°→360° даёт видимый шов («резкий старт» дуги) в точке стыка прозрачного и насыщенного краёв — для обводки прогресс-дуги используй СПЛОШНОЙ цвет (`lineCap: .round` можно оставить).
- Цвета текста/трека в переиспользуемых компонентах (кольца, бейджи) выноси в параметры (`valueColor`/`labelColor`/`trackColor`) со значениями по умолчанию — тогда на тёмном баннере передаёшь белый, а светлые карточки не страдают.
- ⚠️ **Swift Charts: серия наезжает на подписи оси значений. ЧИНИТЬ СРАЗУ, не проверяя.** Симптом: столбик/точка стоит поверх цифр шкалы (`0 1 2 3…`), особенно у правого края; при 2 записях видно только один столбик. Две независимые причины, лечить надо ОБЕ:
  1. **`x: .value("...", index)` с `Int`/`Double` даёт НЕПРЕРЫВНУЮ шкалу**, и крайние марки встают ровно НА границу plot-области — прямо в жёлоб оси. Для столбчатых диаграмм x обязан быть `String` (или `Plottable`-enum) → это band-шкала, каждый столбик инсетится внутри своего слота и до края не достаёт. Для линии/области band недопустим (сломает `interpolationMethod`) — там оставляй непрерывную шкалу, но добавляй запас: `.chartXScale(domain: -0.35 ... Double(count-1) + 0.35)`.
  2. **`AxisMarks(values:)` без `position:` — это `.automatic`**, и SwiftUI вправе поставить подписи значений на TRAILING сторону, ровно туда, где заканчивается серия. Плюс кастомный `AxisValueLabel { … }` меряется для резервирования жёлоба, и вью без собственной ширины меряется ненадёжно → plot-область расползается под подписи.
  Лечение — ОДИН общий хелпер на весь проект (в UI-ките, не в экране), чтобы правило нельзя было обойти на новом экране: `AxisMarks(position: .leading, values: …)` + внутри `AxisValueLabel` текст с `.lineLimit(1)`, `.minimumScaleFactor(0.6)` и ЯВНЫМ `.frame(width:alignment: .trailing)` — именно явная ширина резервирует жёлоб. Проверка: `grep -rn "chartYAxis" --include="*.swift"` должен давать РОВНО одно совпадение — внутри хелпера.
  Отдельно: **нулевое значение рисуется столбиком нулевой высоты и визуально пропадает** — читается как «данные потерялись». Либо оставляй видимой подпись слота по оси X, либо давай нулю минимальный видимый огрызок; молча прятать запись нельзя.
- ⚠️ **`.drawingGroup()` НА ФОНЕ ЛИСТА (`sheet`/`fullScreenCover`) — ЗАПРЕЩЁН. Фон экрана и фон листа обязаны быть РАЗНЫМИ вью.** Симптом: открываешь второй лист поверх первого — у нижнего листа фон обрезается и перестаёт совпадать с его карточкой. Причина: `.drawingGroup()` растеризует сцену в текстуру ОДИН раз по layout-границам, а показывая второй лист, система сдвигает и масштабирует первый — готовая текстура едет ТРАНСФОРМОМ, не перерисовываясь, и разъезжается с рамкой листа. Плюс `.background(...)` берёт размер контента: короткий контент — низ листа не закрыт вовсе. Лечение: держать два фона — полноэкранный (`ZStack{…}.drawingGroup().ignoresSafeArea()`, кэш там нужен и полосы под вырезом лечит именно он) и листовой, БЕЗ `drawingGroup` (три-четыре градиента дёшевы, кэшировать нечего), а хост листа растягивать до карточки ПЕРЕД фоном: `.frame(maxWidth: .infinity, maxHeight: .infinity)` затем `.background(<фон листа>)`. `.ignoresSafeArea()` внутри листа при этом ОСТАВИТЬ — без него оголяется полоса над home-индикатором; виноват именно `drawingGroup`, а не он. Чинить в общем скаффолде листов, а не на одном экране: скаффолд переиспользуется всеми бенчами, баг сразу глобальный. `presentationBackground` не предлагать — это iOS 16.4+, а проекты на iOS 16.0. Проверять: лист над листом и лист с КОРОТКИМ контентом (пустое состояние).
- Тёмная тема: нативные контролы (`TextField` placeholder/ввод, `Stepper`, `Picker`, `Toggle`) берут цвет из системного `colorScheme`, НЕ из `ColorPalette` → на тёмном фоне текст чёрный/нечитаемый, placeholder тёмно-серый. Форсировать в `ContentView` (не App.swift): `.preferredColorScheme(.dark)` + в `onAppear` для всех окон `w.overrideUserInterfaceStyle = .dark` (покрывает `.sheet`/`.fullScreenCover`, куда `.preferredColorScheme` НЕ пробрасывается) + `w.tintColor`/`.tint` = accent (нативный акцент Picker/Stepper фирменным, не синим). Для светлой темы — `.light`.
