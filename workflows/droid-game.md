# /droid-game — собрать Android-игру по образцу или ТЗ

Ниже (в аргументах команды или следом в чате) — флоу-образец игры (ссылка, скриншоты,
описание механики) или ТЗ: $ARGUMENTS

**Сначала прочитай `$HOME/.claude/rules/android-games.md` целиком** — это конвейер и все
накопленные правки. iOS-правила из CLAUDE.md к этой задаче не применять.

Порядок:

1. **Разбор образца.** Выдели из флоу МЕХАНИКУ и структуру напряжения (что игрок решает,
   где риск/награда, темп). Зафиксируй границу оригинальности: своё название, слоган,
   сеттинг, персонажи, палитра (светлота и hue расходятся с прошлыми играми в
   `$PIPELINE_ROOT/android/`), свой OFL-шрифт. Никаких чужих брендов, лого,
   валютных ставок. Если образец — чужой продукт с именем/артом, переизобрети содержание,
   сохранив только жанровую механику. Концепцию в двух абзацах покажи оператору в ответе
   (не жди подтверждения — строй сразу, он поправит по ходу).

2. **Каркас.** Новый проект на РАБОЧЕМ СТОЛЕ (`~/Desktop/<Имя>/`). Врапперы и конфиги —
   по образцу эталона `$PIPELINE_ROOT/android/<reference game>/` (read-only!), свой
   namespace/applicationId. Архитектура — роли эталона с доменными именами: чистый
   MainActivity, AppRoot-гейт с МГНОВЕННЫМ стартом в геймплей, единый ViewModel+StateFlow,
   толерантная персистентность, звуковой singleton со сгенерированными звуками.

3. **Ядро игры.** Симуляция чистыми функциями + frame loop с dt-клампом. Честность
   арифметикой: щадящий хитбокс, препятствия ниже апекса прыжка, прогрессивная сложность
   с доказуемой проходимостью. Управление: тап + явные кнопки. Подсказки первого раунда
   вместо онбординга.

4. **Наполнение.** Пикапы на трассе, таблички/вехи прогресса, декор на полном параллаксе,
   живой фон (птицы/дым/флаги от одного clock). Геймификация: гараж с реальными эффектами,
   ранги, ачивки с прогрессом, сложности по рангам.

5. **Арт.** Пока ассетов нет — рукописный вектор по правилам справочника (юниты сцены,
   метры мира, лица внутри головы, кламп рук). Ассеты дизайнеров придут позже — под них
   есть `/droid-assets`.

6. **Сборка и проверка.** `assembleDebug` до BUILD SUCCESSFUL; вычитка цепочек
   UI→метод→сохранение→результат; каждая цифра UI = цифре движка. Приложение в эмуляторе
   НЕ запускать — тестирует оператор (эмуляторы Pixel_8 / Pixel_Tablet готовы).

7. В финальном ответе: что за игра, все экраны, механика с числами баланса, что проверить
   руками. STORE_LISTING.txt и упаковку не делать здесь — это `/droid-pack` по команде.
